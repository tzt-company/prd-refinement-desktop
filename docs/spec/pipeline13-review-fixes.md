# Pipeline 13 二次审查修复方案

## 目标

修复二次审查真实复现的五条路径：边界返工耗尽后继续运行、删除澄清误销需求问题、局部上下文遗漏跨来源直接依据、来源型澄清看不到同源需求、字段证据缺失时自动扩散来源。

## 状态规则

- 内外层共同使用每项边界问题三次无变化预算；预算耗尽后进入最终失败门禁。
- 删除已回答澄清只处理 `source-decision` 问题。复合明细问题必须由候选修复和局部复核独立关闭。
- 局部上下文保留直接需求和同源需求，再从同功能中按问题文字选择最多四条高相关需求；避免全目录扫描。
- 最终澄清检查从来源引用反查同源需求，使仅关联原文的澄清也能判断是否已有答案。
- pipeline 14 的模型需求输出必须显式提供逐字段 `evidenceBindings`；旧数据读取仍保留历史兼容，旧检查点不续跑。

## 验证

五条失败反例进入正式单元或调度器测试；全量测试、类型检查、生产构建及本地 Electron 重启后才交付。
