# 原文引用失败的根因与修复方案

日期：2026-09-11。状态：实施前方案快照。源码基线：`2be0a6e`。

目标：消除由模型重新抄写原文而产生的来源定位失败，并保证引用范围经过候选识别、统一、返工、细化、展示及交付后不丢失、不扩大。

本轮仅检查源码、任务快照并执行最小复现；未继续改业务代码、重试任务或发布。新增本文件是因为此前两个相关 spec 是既有开工前快照：`feature-source-references.md` 采用模型输出 quote 的旧选区协议，`model-output-failure-containment.md` 针对局部修正失败隔离，均不能代替本次引用全链路协议调整。

## 1. 当前错误到底表示什么

`features[3].sourceRefs[0] 引用文字不在指定原文中` 表示某一次模型响应的第 4 个候选功能、第 1 处引用所提交的 quote，不是它指定的 sourceUnit 文本的连续子串。它不是最终功能 F-004，也不表示 PRD 缺少业务要求。

`electron/domain.ts:24` 的解析器先查 sourceUnitId，再在 `asset.extractedText ?? excerpt` 内做 `indexOf(quote)`。找不到或出现多次均拒绝。它不在相邻块、章节 context 或其他文件中查找。

当前任务 `T-7466A157` 的独立只读回查结果：

- 状态 failed，attempt=2，进度 12.5%；375 个来源单元，17 个候选批次。
- 候选识别和独立检查各完成 15/17；未完成的是数组下标 12、14，即第 13、15 批。
- 第 2 次执行的这两个候选批次各发生 try1、try2，两次调用均有模型输出用量记录，最终仍为引用校验失败。
- 定向提示补丁 `2be0a6e` 已实际参与该次重试；因此，提示更严格并没有解决真实任务。

证据文件：`%APPDATA%/prd-refinement-desktop/analysis-tasks/T-7466A157.json`。分析时文件 SHA-256 为 `1D2727EDDFE3B9016D843B48E630102653C38CC167B6990109F11CA041C98F87`。

**取证盲点**：失败响应未持久化，任务内只有报错字符串和调用用量。`electron/runtime.ts:58` 使用 ephemeral 调用，`electron/scheduler-v2.ts:549` 仅在内存中将上一响应送入重试。本次检查任务的 runtime 子目录也没有响应文件。因此不能断言这次具体 quote 是改了空白、拼了相邻块、选错了编号还是改写了措辞，更不能虚构那条失败原句。以下材料问题和范围丢失均有独立证据，但不能冒充已找回的失败响应。

## 2. 已确认的根因与同源缺陷

### 2.1 引用协议把机械定位交给了生成模型

候选 schema 要求模型同时完成业务分组、复制长来源编号、逐字抄写唯一原文片段，再由程序反向搜索字符位置。协议允许整块引用，但模型仍会主动输出 quote。代码依据为 `electron/scheduler-v2.ts:30`、`electron/domain.ts:24`。

模型抄写的字符串不是可靠的位置标识：换行、空格、标点、行内标签、重复文本都可能造成失败；重复整份响应也会引入其他位置的新错误。已有回归测试只证明了模拟模型按提示删除 quote 时可以成功，没有证明真实模型会这么做。

这类错误可以通过去掉模型生成 quote 这一环节从机制上消除；不应靠无限重试维持任务运行。

### 2.2 HTML 来源单元破坏了真实阅读结构

`electron/document-assets.ts:152` 对每个非空 `#text` 节点单独建账；表格只传表格位置上下文。`electron/scheduler-v2.ts:69` 再按单元数和字符数批处理，没有列表项/表格行边界。

真实文件第 578–579 行：

```html
<li>Included Version 表示该数据集被加入的全部版本，不读取
<code>tw_processes.version</code>；</li>
```

当前任务将它拆成三个来源单元，末尾编号分别为 0282、0283、0284：

1. `Included Version 表示该数据集被加入的全部版本，不读取`
2. `tw_processes.version`
3. `；`

模型把这三块理解成完整一句是合理的，但将整句作为任何一块的 quote 都必然校验失败。NULL 等行内代码也有同样的拆碎现象。第 13 批实际包含上述碎片。

第 15 批包含的单元 0332 保留了 `关联\nID`。直接调用当前编译产物的 `acceptDirectFeatures` 验证：完整原文被转换成 `[0,61)`；仅将空白折叠成空格，就得到同类“不在指定原文”报错。这是同类触发的复现，不是恢复了历史失败响应。

另有实际上下文串用：正文“5.4.7 导出”的章节路径包含内嵌 iframe 的“发现可合并的同名生产活动”及示例“氧化铝……”标题。`enrichSourceContext` 对展开后的全列表使用一个标题栈，没有嵌入文档作用域（`electron/source-units.ts:7`）。这增加了来源误选和理解错误的机会。

原始任务输入仍存在于其 inputSnapshotPath 下。该 HTML 文件 SHA-256 为 `03aa77752b175deb1fbeb22913071e1dc49bc41926ba53158de86677683c0fae`。任务 project.sourceHash 是索引 manifestHash（`electron/material-bundle.ts:170`），不能当作单文件哈希与它直接比较。

### 2.3 正确引用在后续链路中仍会丢掉范围

两处确定性缺陷：

- `electron/domain.ts:29`：接收到已有 `{sourceUnitId,start,end}` 时，只要没有 quote，就返回 `{sourceUnitId}`，丢弃 start/end。模型输出协议与已解析领域对象没有分清。
- `electron/domain.ts:179`、`:186`、`:195`：功能统一以 sourceUnitId 集合编译来源，没有保留候选的区间。

本轮对当前编译产物实际执行的最小复现：

```text
来源：允许撤回。允许导出。
候选选区：允许撤回。
首次解析：[{sourceUnitId:"S1",start:0,end:5}]
将已解析候选再次交给 acceptDirectFeatures：[{sourceUnitId:"S1"}]
单候选映射到单功能后：[{sourceUnitId:"S1"}]
```

所以“失败时自动删除 quote”会进一步固化范围扩大的问题，不能采用。

关联链路也须一起收口：细化读取完整单元（`electron/scheduler-v2.ts:381`）；Agent Markdown 和 Excel 按 sourceUnitIds 输出整块（`electron/export-agent-package.ts:76`、`electron/export-excel.ts:20`）。完整上下文可以保留，但必须与真正选中的证据分开标识。最终图校验主要检查来源 ID，没有统一校验所有选区的边界和快照归属（`electron/domain.ts:228`）。

### 2.4 报错与重试缺少可定位信息

校验只抛第一个字符串错误；重试携带完整旧响应和原请求。没有持久化失败 quote、对应来源、差异、节点和批次。并行候选阶段还统一设置 activeStage=2，导致候选识别的输出失败可能把候选完整性检查标成 failed（`electron/scheduler-v2.ts:311`、`:544`）。

用户只能看到内部数组路径，无法判断是材料、业务问题还是平台故障。此类平台错误不应生成业务澄清，也不能被列为“可忽略”从而放行交付。

## 3. 方案比较

| 方案 | 优点 | 排除/选择理由 |
|---|---|---|
| 加强提示、增加重试、换更强模型 | 改动小 | 已有真实反例；只提高成功概率，复制原文这一步仍不可靠，不作为根治 |
| 空白归一化/模糊匹配，或找不到时删除 quote | 容易让任务继续 | 无法解决跨块与错来源；还可能扩大证据范围或错误定位，不作为验收通过路径 |
| 修好 HTML 切分，继续要求模型输出 quote | 能缓解当前材料触发 | 重复文本、转录、返工和范围丢失仍存在，属于必要的材料修复但不是完整方案 |
| 程序生成可选证据位置，模型只选择，程序解析并全链路保留 | 将文字复制与位置计算移出模型输出 | 推荐；需同时修改导入、引用契约和下游传递，是针对同因问题的完整范围 |

## 4. 推荐实现

### 4.1 先恢复来源结构

- HTML 段落、列表项、表格行成为上下文容器；code、strong、span 等行内节点并回所属容器。保留表头、单元格边界及节点位置，避免只剩孤立字段值。
- 按文档与 iframe 建立独立结构作用域，进入/退出嵌入文档时保存并恢复父文档标题栈；跨文件同样隔离。
- 批处理尊重容器边界。超大容器分片时保留容器身份、表头及前后上下文，不能无提示截断条件和结果。
- 原文件保持不可变。供分析的规范文本只生成并冻结一次，保留到原始节点的映射；后续提示、定位、展示、导出使用同一规范文本，不在各阶段各自折叠空白。
- 排版源码与交互脚本仍保留原始证据和明确角色，不以清理噪声为由静默丢弃可能包含的业务内容。

### 4.2 模型选择程序已生成的证据位置

复用 SourceIndex 与任务输入快照，增加它们的证据选区投影，不另建可独立修改的第二份来源正文。

程序按结构和确定性句子/分句边界生成可选片段，记录到现有来源单元的 UTF-16 左闭右开范围。超长单句再按确定性边界分片，保留相邻上下文；切分是定位辅助，不生成或猜测原子业务需求。覆盖检查确认正文字符与标点未被丢失。

模型看到的内容示例：

```text
E17：允许撤回。
E18：允许导出。
```

模型返回的来源部分为 `evidenceIds:["E17"]`，程序解析为已有的 SourceRef 位置。E17 是任务证据目录提供的短引用标识，不是模型自由创建的实体。

- 模型不再返回 quote，也不计算 start/end；名称和需求表述仍由模型正常生成。
- 同一文字出现多处，各位置有独立标识，不靠字符串搜索消歧。
- 不连续证据选择多个标识；同一证据允许被多个功能共享。
- 整段引用必须明确选择程序给出的整段项；非法引用不会自动扩大成整段。
- 请求只能选择本节点实际提供/已读取的证据；额外所需证据通过现有有界读取机制取得。未知、越权范围、过期标识均拒绝。
- 证据目录绑定输入快照和定位协议版本。重启读取同一目录，不根据新的分词/切分结果悄悄重算旧位置。

### 4.3 已解析引用只走领域对象路径

模型选择器和领域 SourceRef 使用不同的解析入口。模型选择器只接受证据 ID；领域对象校验快照、来源、整数边界与 `0 <= start < end <= text.length`，不会因缺少 quote 而降为整块。

- 合并取精确区间并集，不以最小 start、最大 end 包住中间未选内容。
- 拆分按证据标识/区间分配到目标功能，检查无越界及无遗漏；有意共享允许重叠。
- sourceUnitIds 从引用计算，用于索引与图查询，不能成为独立可写的第二份真相。
- 返工回传、检查点恢复以及未修改条目保留原区间；业务无变化的条目不再让模型重写来源。
- 功能、需求字段证据、澄清和关系共用同一引用解析器，避免只改 features 后在 clarifications/evidenceBindings/relations 再次失败。
- 对 explicitAcceptanceConditions 这类要求逐字摘录的字段，同样由模型选择证据、程序取回文本，避免保留另一套自由抄写与不同的空白校验规则。

### 4.4 细化、展示与交付保持同一证据范围

细化请求明确分成“本功能选中证据”和“阅读上下文”；上下文帮助理解，不能自动变成该功能的业务范围。额外来源必须显式选择并经过相同校验。

页面、JSON、Markdown、Excel 共用选区读取结果，原文正文及高亮范围一致；完整段落和表头可展开阅读，但不能冒充选中内容。图片与 OCR/视觉转录保持来源类型区别，图像没有精确坐标时如实显示整图引用，不伪造字符在图片上的位置。

最终校验遍历所有实际引用，而不只检查 sourceUnitIds 存在。引用定位有效与业务语义正确仍分别验收。

### 4.5 有界修正与可复现诊断

保留现有有界重试，不增加无限循环。校验以结构化结果一次列出当前响应所有非法引用，明确节点、批次、对象、字段和允许选择的证据。仅重新提交失败节点；已成功检查点保留。

在任务本地运行目录记录必要的失败输出、证据目录版本/哈希和校验结果，并绑定调用序号；避免将凭据、环境变量和原始 stderr 写入诊断。诊断不进入用户的业务交付包。历史失败响应无法补造，实施后用冻结输入重放形成新证据。

正确记录实际失败节点。用户文案示例：“平台未能完成‘导出字段规则’的来源定位，已保留其他处理结果。”附文件、章节和可读原因；内部编号与字段路径收进诊断详情。修正耗尽后保持平台处理失败/未完成状态，禁止转换为业务待澄清或成功交付。

## 5. 实施顺序与影响范围

1. 以本任务固定 HTML 和最小反例建立复现，先补诊断及独立失败定位。
2. 修复 HTML 结构、嵌入文档作用域，建立冻结证据目录与唯一解析器。
3. 一次性切换所有模型节点的来源选择契约；补齐统一/拆分/返工/检查点的区间保留。
4. 统一细化输入和页面、JSON、Markdown、Excel 的选区读取，补最终完整引用校验。
5. 用原始固定文件在新定位协议下完整重跑，并回读实际 Electron 与交付包。

涉及 `electron/document-assets.ts`、`electron/source-units.ts`、`electron/source-index.ts`、`electron/domain.ts`、`electron/scheduler-v2.ts`、`electron/audit-repair.ts`、相关类型、结果读取/导出及对应测试。诊断复用现有任务运行目录，界面沿用现有错误与详情区域；不扩建另一套工作流。

定位与模型协议变化需提升检查点协议版本。当前 15/17 个批次不能直接拼到新索引上；保留旧任务作诊断，用它保存的原文件快照重新建账并分析，不要求用户改 PRD 或重新找文件，不猜测迁移旧范围。新协议内的中断恢复仍精确复用同快照、同版本检查点。

现有八节点职责、功能名称生成、三级业务澄清和运行并发不因此重新设计。实施时同步 README；本方案不修改当前能力声明。

## 6. 验收标准

| 验证项 | 必须成立 |
|---|---|
| 当前 HTML 的行内 code / NULL | 完整句子和原始节点位置均可读，不能再形成无上下文的半句 |
| 表格、批次边界 | 条件和预期结果保持行关系；跨批仍携带表头与容器身份 |
| iframe / 多文件 | 子文档标题不污染父文档或其他文件 |
| 空白、标点、重复原句 | 模型仅选 ID，程序取回固定文本；不会依赖模型重新抄写，也不错误选到相同文字的另一处 |
| 改写、未知 ID、过期 ID、越界 | 确定性拒绝；不自动删引用、不扩大范围、不放行成功 |
| 同段两功能 | “允许撤回。允许导出。”分别选择；统一、拆分、返工与恢复后仍各保留正确区间 |
| 非连续选区与共享条件 | 不填充中间空隙；共享范围可复用，其他功能要求不会被带入 |
| 全节点协议 | features、clarifications、evidenceBindings、relations、原文明示验收摘录均走相同证据选择机制 |
| 页面与交付包 | JSON 位置、页面高亮、Markdown、Excel 引用片段一致，来源快照不可漂移 |
| 失败隔离与诊断 | 一次返回全部可判断的引用问题；节点/批次正确，能离线复现；平台错误不生成业务澄清 |
| 当前真实任务 | 在冻结原文件的新执行中通过候选及后续全部节点；原失败第 13、15 批相关内容逐项核对，不能靠丢项通过 |
| 语义独立检查 | “不读取 tw_processes.version”、版本聚合、合并后另行确认生成版本、单组原子性等真实规则保留；结构通过不代替此检查 |

验收时维护 `docs/acceptance/source-reference-integrity/` 下的 matrix、每轮证据和报告；本轮只完成分析，不填写修复 PASS。

可根除的是“模型复制的 quote 与原文不一致导致位置解析失败”这一机制，以及引用区间在传递中被静默扩大这一确定性缺陷。模型仍可能选择语义不相关的合法证据，因此语义审计必须保留；不能以消除该报错承诺所有分析任务永不失败或语义百分之百完整。
