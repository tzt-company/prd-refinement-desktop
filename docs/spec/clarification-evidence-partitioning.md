# 澄清证据分片与跨批一致性

## 现状与原因

35 个相同业务澄清分为 12/12/11 后仅批内合并，终态仍有三个同义项，却通过澄清检查。单个澄清关联十二条长需求时，按问题数量拆分无效，最终请求 21,968 tokens 超过 20k。

## 实施

1. 复用原有证据编译、提示计量和动作校验。普通范围在预算内仍一次完成；超大范围先拆问题，再将单项问题的完整需求和对应原文分片，所有原文均有片覆盖，不截断业务文本。不可拆分的单个条目仍超过硬预算时明确失败。
2. 单项分片都保留问题则保持开放；存在删除或修订候选时独立汇总各片理由，仅能选用已经校验的候选或保持开放，不能投票删除或生成新证据。汇总本身也接受完整提示预算检查。
3. 批内动作应用到暂存快照后，跨批核对剩余问题的完整业务描述和来源身份。按预算组成问题组，对全部组对执行核对，覆盖每一对问题；只允许合并或保持独立。合并关系与明确保持独立的关系冲突时失败，不静默选一方。名称或表述相同不是自动合并依据。
4. 结果以请求内容指纹缓存到检查点，失败或取消不提交部分澄清修改；重试复用完成分片。全部有效性和跨批检查通过后再应用最终快照。
5. 升级 pipeline 15，统一版本常量供桌面和验收脚本使用。旧契约检查点不混用。

新增 electron/clarification-reconciliation.ts：分片规划、汇总与跨批核对已形成独立职责，避免继续把递归调度与数据校验堆入 scheduler-v2.ts；实际模型调用、并发槽位和持久化仍复用调度器。

## 验证

两条已复现反例必须反转；另外覆盖独立问题不合并、单项分片已有答案/矛盾、非法动作、后续分片故障重试和取消无部分提交。完整测试、类型检查、构建、本地桌面启动独立取证。真实模型语义稳定性保留为后续验收，不用模拟输出声称通过。
