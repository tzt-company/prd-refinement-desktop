# 模型输出校验失败的隔离方案

## 目标

模型在局部修正中连续返回不符合结构、引用或逐字摘录契约的数据时，不得污染已有结果，也不得让整项任务丢失可交付产物。失败必须收敛为可追踪的局部拒绝记录；尚未被任何需求或澄清承接的原文必须生成显式人工确认项。

## 根因

- 严格校验能够拒绝伪造的 `explicitAcceptanceConditions`，但两次校验失败后抛出的普通错误无法与 Runtime/网络故障区分。
- 局部修正阶段没有失败隔离边界，一个候选输出无效会终止整个任务。
- 局部修正提示允许返回完整需求对象，却没有明确要求未被问题指向的字段原样保留，增加了模型重写逐字摘录字段的概率。

## 修复

1. 将“模型正常返回、但连续两次未通过输出校验”标记为专用错误；Runtime、网络及进程异常继续原样抛出。
2. 局部修正提示要求未涉及字段逐字复制；`explicitAcceptanceConditions` 未被问题明确指出时不得改写，新需求默认返回空数组，只有原文明确给出验收条件时才允许逐字摘录。
3. 局部修正候选连续两次校验失败时，拒绝整个候选且保留原审计问题。对于仍未被需求或澄清承接的范围内原文，确定性生成待人工确认项，使来源不丢失、无效内容不入库、任务仍能生成带未解决问题的审阅产物。
4. 审查历史记录拒绝原因，不能把失败候选显示成“无新增问题”。
5. 模型审计与脚本覆盖检查指向完全相同的未承接来源集合和同一功能时，合并为一个修正范围；仅部分重叠的来源集合不得传递合并，避免形成模型难以完整处理的过大范围。
6. 逐字摘录匹配统一移除空白并忽略拉丁字母大小写；其他字符和符号仍按原值比较，避免合法引用误拒绝或符号差异被放过。
7. 模型 JSON 通过字段校验后，候选预应用发现来源覆盖、图关系或事务约束不成立时，同样按模型输出校验错误隔离，不升级为任务级故障。

## 验证

- 伪造验收条件连续返回两次：任务完成、原审计问题保持开放、无效验收条件不入库、未覆盖原文生成待确认项、拒绝原因进入检查点。
- Runtime 调用抛错：任务仍失败，证明故障隔离没有吞掉基础设施异常。
- 全量类型检查、测试、构建通过。
