# PRD 资料包识别与索引方案

日期：2026-09-10  
状态：待实施方案；本文不表示功能已实现。  
范围：主 PRD、补充文档、原型、图片和资料目录；暂不提供或接入业务代码、业务数据库。

## 1. 目标与现状

将任务输入从一个 PRD 文件升级为一个可版本化的资料包。先完整登记所有提供文件、识别内容和引用关系，再让需求分析各环节按稳定来源编号查阅。索引完整性、内容可读性、业务语义完整性分别验收。

当前实现证据：
- electron/main.ts 的 projects:import 只接收一个路径，立即解析为一个 PrdProject；目录被拒绝。
- src/App.tsx 的 importTask 在导入成功后立即 startAnalysis，没有资料确认阶段。
- src/types.ts 的 PrdProject 只有一组 sourceName/sourceHash/rawText；SourceUnit 缺少文件级归属和原文坐标。
- electron/source-units.ts 的 buildSourceUnits 每次从 S-001 编号，location 主要是提取文本行号，不能直接当作原文件行号。
- electron/scheduler-v2.ts 的原文建账遇到任一未处理来源就失败，没有“等待补件”业务状态。
- T-36AB17B1 实际问题：HTML 内嵌原型引用 assets/filter.svg、assets/copy-document.svg，单文件输入未提供依赖目录。仅增加文件扩展名不足以解决资料完整性。

可验证目标：
1. 每个任务明确一个主 PRD，支持多个补充文件、一个或多个目录。
2. 提交前展示实际文件清单；没有被静默遗漏的文件、引用和解析失败。
3. 保留目录路径并解析相对引用；同名或歧义不得猜测绑定。
4. 后续结果可追溯到资料版本、具体文件及其原文位置。
5. 缺件进入可恢复状态，不重复触发无意义的分析失败。

## 2. 范围与非目标

一期输入：HTML/HTM、DOC/DOCX、PDF、Markdown/TXT；PNG/JPEG/WebP/GIF 图片；SVG 作为资料资源增加受控栅格化读取，不执行活动内容。沿用 DOC 的本机 Word 依赖，并在预检时显示缺少依赖。

一期不接入业务仓库或数据库，不建设向量数据库、云文件同步、网页抓取和通用代码执行环境；不自动下载外链附件，不执行 HTML 脚本。目录中不支持的文件仍登记，显示原因和处置入口。压缩包一期不自动解压，提示解压后添加目录。

“不提供代码”指不上传项目源代码；HTML 中自带的原型交互脚本仍属于已提供文档内容，只作来源数据保留，不能成为对 Agent 的指令。

## 3. 用户流程

### 3.1 新建资料包

新建任务页分成三个区域：
- 主 PRD：一个文件，可选择或拖入；必须由用户明确指定。
- 补充资料：可添加多文件、选择目录或拖入目录；显示目录树、文件数、体积和用途。
- 资料处理状态：展示登记、识别、索引进度及缺失项。

添加只建立草稿，不直接启动需求分析。用户点击“识别与建立索引”后，先生成文件快照再处理；按钮在处理中防止重复提交，允许取消。索引就绪后点击“开始需求分析”。

默认角色：主文件为主 PRD；其他为补充参考；被显式引用的图片、附件同时建立引用关系。可以将历史版本标为“历史参考”，或明确排除资料并填写原因。角色表示用途，不表示已经验证可信。

目录枚举保留全部文件条目；系统临时文件、链接、权限失败项单独显示，不静默消失。Windows junction/symlink 不跟随，防止越界和循环；用户可明确另选真实目录。

### 3.2 识别结果页

显示“文件登记 / 内容读取 / 索引构建”分项计数，不伪装成精确的语义完成百分比。

文件列表列：路径、角色、格式、版本、读取状态、引用情况、问题。可查看目录树、按问题筛选、预览正文或页面、查看原文位置。

缺失项卡片列出：哪个文件引用、引用路径、原文位置、影响范围、补件动作。提供“添加文件”“添加目录”“关联已有文件”；只有用户明确确认是非业务装饰或不适用资料，才允许排除，并保存依据。

例：主文档引用 assets/filter.svg。添加 assets 目录后，界面预览它将挂到主文档相邻的 assets/ 路径；确认绑定后重建关系。不能把来自其他目录的同名图标自动替代。

### 3.3 补件和继续

识别期间、尚未开始需求分析时：补件生成资料包新版本，复用哈希与解析器版本相同的解析结果；重新计算引用和索引。全部相关缺口解决或完成有依据的排除后，进入“索引就绪”。

需求分析开始后：锁定本次运行的资料包版本。新增、替换、删除资料生成新版本，用户选择“按新资料重新分析”；保留旧运行结果，一期重新执行语义分析，不承诺跨版本精准局部续跑。

## 4. 第一阶段：资料识别与索引

### 4.1 文件登记与不可变快照

Electron 主进程枚举文件、记录规范化相对路径、格式、大小、SHA-256、来源角色和文件引用关系；原始内容复制进任务资料目录。复制后重新核对哈希，源文件在复制过程中变化则提示重新添加。

文件身份独立于文件内容：同一文件更新保留 fileId 并递增版本；同内容不同路径保留两个文件条目，底层内容可以共享。删除后重新编号、按文件名全局去重均禁止。

大目录按批枚举，显示数量与体积并支持取消；设置可见的数量、单文件大小、总大小和解析耗时上限，超限提示用户缩小范围，不只处理前 N 个。具体数值在代表性样本和桌面内存实测后确定并写入配置说明。

### 4.2 格式识别与内容解析

扩展名和文件签名共同校验。逐文件解析，保留以下位置：
- PDF：页码、文本块；完整页面图像关联同一页。
- DOCX/DOC：段落序号、表格/行/单元格、图片或包内组件位置。不能承诺从 DOCX 直接得到准确打印页码；DOC 转换文件与原始文件关联。
- HTML：原文行列/DOM 定位、标题路径、表格位置；内嵌文档有父文件和 iframe 定位。
- Markdown/TXT：原始行区间。
- 图片：文件或嵌入位置、视觉转录结果、可读性、模型与处理版本；转录不冒充原文。

先确定性解析和建账，再对必要图片/页面进行视觉识别。图片、表格标题与上下文一起保留。主文档、补充参考、示例、脚本、样式、历史资料使用不同来源标签；脚本与样式不能按普通业务段落无差别抽取为需求。

动态原型：保留静态 DOM、内嵌文档、脚本/数据定义，标记动态生成区域。保存脚本源码不等于已经读取所有交互状态；无法可靠重建的内容列为不确定项，可补充截图或说明，不能宣称完整渲染。

### 4.3 引用解析

记录 ReferenceEdge：来源文件及位置、原始引用、目标 fileId/内嵌资源、绑定状态和依据。

解析顺序：
1. srcdoc/data 资源归属原文件，解码后建立内嵌资源，不访问网络。
2. 相对路径基于引用文件的逻辑目录解析，只在已提交资料范围内寻找。
3. 单独提交目录带命名空间；不能自动压平。主文档之外的目录挂载点由用户确认。
4. 找不到目标记 missing；多个可选绑定或大小写冲突记 ambiguous，提示用户关联。
5. 网络资源记 external，保留地址并提示上传副本或明确排除；不后台自动下载。

路径归一化需处理分隔符、URL 编码、大小写和 ..；归一化后越出已提交范围即拒绝自动读取。目录路径与磁盘绝对路径分开，索引不依赖源文件原位置继续存在。

### 4.4 内容索引

按文件、章节、段落、表格行、图片与原型片段建立 SourceUnit。建议稳定标识 F-xxxx/U-xxxx；标识在同一文件修订中稳定，变更版本不能复用到内容不同的单元。新解析器版本触发重新识别，旧引用不静默漂移。

每条单元记录 fileId、fileRevision、类型、章节路径、原文定位、原文/提取文本引用、上下文、读取状态及用途标签。

一期建立本地确定性索引：文件目录、标题目录、单元 ID 映射、引用邻接表、关键词索引。中文分词可先采用可复现的词片段或 n-gram 策略；排序结果必须能回到原文。索引存放本地任务目录，可重建；不依赖业务数据库，也不引入服务端检索设施。

## 5. 后续环节如何使用

提供统一、只读的来源访问接口：
- listSources：按文件、角色、章节、读取状态分页列出单元。
- readSourceUnits：按稳定 ID 读取原文及相邻结构；返回版本和原文位置。
- searchSources：关键词、标题、文件及角色过滤；明确返回截断情况、分页游标及匹配片段。
- getReferences：读取引用目标、缺失项与反向引用。

当前 AnalysisRuntime 主要接收 prompt，不能假定已有模型工具调用协议。一期由现有 Node 调度器调用这些接口，组装候选来源包；需要扩展阅读时，模型返回结构化来源请求，调度器校验 ID、范围与预算后读回。模型不得直接读任意磁盘路径，也不得自行查询别的任务。

功能识别、完整性检查仍按应处理来源清单遍历。搜索用于定位和补充关联证据，不替代覆盖台账。每个应处理单元都要有明确处置：需求、上下文、示例、历史参考、待澄清或排除；“搜索未命中”不算已处理。

主 PRD 决定当前任务范围；补充资料可解释、细化和发现冲突，但不能未经确认扩大范围或覆盖主 PRD。显式冲突同时保留两侧原文、角色和版本，形成待澄清项。

需求明细、审计问题和 Excel 引用需包含文件名/逻辑路径、定位及来源编号，不能再只显示“第 N 行”。

## 6. 状态与失败语义

资料包状态：draft → indexing → ready；存在来源缺口时进入 needs-materials；基础设施或解析进程异常为 failed；主动取消为 cancelled。

必须补齐或确认的缺口：主 PRD 不可读、显式引用目标缺失、内容相关性未知的资源、来源绑定歧义、必要原型状态无法读取。不能自动推断“图标不重要”后放行。

已明确的排版信息不构成缺口；已提供且可解析的补充资料要完成登记与处置。非业务装饰、重复内容或明确不适用资料可以被排除，但需记录理由和操作来源。缺口数量为零与语义审查通过分别展示。

needs-materials 不占模型执行槽，不自动重试，不把等待时间累计成模型运行时间；补齐前可浏览已识别资料，不产出依赖缺失内容的通过结论。

## 7. 存储与变更范围

延续 Electron userData 文件存储，原文件快照、解析产物、索引和分析结果分开；不引入业务数据库依赖。

建议新增概念：MaterialBundle、MaterialFile、ReferenceEdge、MaterialIssue、BundleIndexRevision。PrdProject/AnalysisTask 引用 bundleId 与固定 revision。来源身份和解析状态由资料包拥有，分析任务只保存语义处理结果和来源引用。

模块职责：
- src/App.tsx / styles.css：资料组装、目录预览、索引进度、缺件处置和查询预览；有界列表或分页。
- electron/main.ts / preload.cts：文件/目录选取、资料登记、索引任务、只读查阅 IPC；调用方与任务归属校验。
- electron/document-assets.ts：继续复用各格式解析；返回文件内定位、资源和引用，不承担跨文件绑定。
- electron/source-units.ts：补充文件级身份与定位；原有字符覆盖改为逐文件校验。
- 新增资料包模块：负责快照、枚举、绑定、索引版本。现有文件职责不适合容纳整个资料生命周期，故独立模块有明确理由。
- electron/scheduler-v2.ts：需求分析只从 ready 的固定资料包开始，使用来源访问接口；保持现有有界并发与取消代次屏障。
- electron/export-excel.ts：扩充多文件来源显示和跳转。

失败恢复采用临时目录写入、完成后原子提交清单/索引版本；未提交产物不显示 ready。重启恢复 indexing 时不能把半成品作为有效索引。

## 8. 旧任务与当前案例

不批量改写既有任务的来源编号和检查点。旧版任务继续查看、导出；若要使用补件能力，创建新的资料包版本和分析运行，并保留旧任务关联。缺少原始文件快照的旧任务必须重新提供原文，不能从已提取文本假造原件。

T-36AB17B1 作为首个验收案例：导入相同哈希主 HTML，登记内嵌原型及三处图片引用；初始应显示两个待补充文件、三处受影响引用；添加正确目录后按相对路径绑定并读取 SVG，缺口解除后才开始需求分析。无关同名图标不得自动替代。

## 9. 方案比较

| 方案 | 优点 | 不采用或采用的原因 |
| --- | --- | --- |
| 全部文件拼成一段文本 | 开发量较小 | 丢失文件边界与版本，难以解决引用和重名，不采用 |
| 只建向量检索库 | 语义搜索灵活 | 召回不确定，无法替代来源覆盖，还增加持久化依赖，一期不采用 |
| 文件清单＋结构化单元＋引用图＋本地关键词索引 | 可定位、可重建、可核对覆盖 | 推荐；后续有真实检索质量证据时再增加语义检索 |

## 10. 实施顺序与门禁

| 步骤 | 交付 | 进入下一步的条件 |
| --- | --- | --- |
| A 资料输入与快照 | 主 PRD、多文件、目录、逻辑路径及清单 | 原生选择和拖放均实测；取消、重名、链接、越界、文件变化有证据 |
| B 识别与引用索引 | 多文件定位、内嵌资源、SVG、缺失与歧义绑定 | 每个文件有处理状态；原型及引用夹具通过；不能靠忽略资源放行 |
| C 资料预检与补件 | needs-materials、目录挂载预览、补件重建 | 缺件可定位、补齐后恢复、重启不丢状态 |
| D 后续分析与交付 | 固定版本来源查询、全量处置、跨文件结果追踪 | 多文档真实样本分析与 Excel 引用回读通过 |
| E 桌面部署验收 | 当前用户实例、原生文件/目录选择、拖放及版本更新 | 确认单实例及实际运行版本，不能只验证隔离实例 |

开发开始后在 docs/acceptance/material-bundle-index/ 维护 matrix.csv、每轮 round-N.md 和跨轮 scripts；全绿后写 report.md。本文保持开工前方案快照，不用实施结果倒改方案。

## 11. 最小验收矩阵

1. 单主文档、多个补充文档、嵌套目录均正确登记；来源总数可与磁盘枚举回查。
2. 跨目录同名文件保持独立；同哈希不同路径仍可正确绑定引用。
3. HTML srcdoc/data 原型、相对资源、路径编码与深层引用可定位；循环、越界和外链有确定结果。
4. PDF 扫描页、DOC 转换、DOCX 图片、SVG 图标分别实测；读取失败不得报 ready。
5. 缺件只进入 needs-materials；补入正确文件恢复，补入错误同名文件不能解除。
6. 目录取消、解析超时、缺权限、文件中途变化、磁盘写入失败和应用重启均不产生虚假完成状态。
7. 来源列表分页、查询截断、中文检索、长表格和大文档预算有明确反馈。
8. 主 PRD 与补充资料矛盾时形成待澄清项；历史参考不自动覆盖现行需求。
9. 每条结果引用能定位到正确文件版本与原文位置；所有应处理来源都有处置。
10. 分析中补件不改变旧运行输入；新版本运行不复用失效语义结论。
11. 当前失败案例从两文件缺失到补齐后索引就绪完整演练，未提供真实附件前标记待验证。

## 12. 证据边界

本方案尚未实施。现有单文件解析和任务机制可复用，但目录组装、资料包状态机、引用绑定、稳定多文件定位和统一来源查询均需开发。

文件清单一致、逐文件字符账本一致、所有显式引用已处置可给出程序化校验；OCR 准确性、原型状态理解与需求语义完整性需要样本对照及人工审阅，不能由索引完成推出。
