## 修复结果

- 审计问题先读取所属功能的全部相关需求和来源，确认成立后才进入修正。
- 复核分别返回原目标结果、候选引入的回归、修改前已存在的旁支问题。原目标解决且无回归时提交候选，旁支问题独立登记。
- 修复候选以 `planned → candidate-ready → committed/verified-rejected` 持久化；中断后从候选复核继续。
- 功能边界、需求明细和需求关系均有实际消费者。没有所属功能的来源遗漏回流到功能边界节点。
- 来源内容角色使用 `contentRole`，不再与功能 `kind` 共用同名字段。
- 待澄清补漏使用澄清专用输出契约；重复澄清由平台合并，禁止生成 `Q → Q` 引用。
- 仅剩业务阻塞时，桌面端显示“需要业务确认”，不显示“继续平台整理”。
