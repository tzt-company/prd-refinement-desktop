# Round 15：真实检索与最终澄清预算修复

## 修复

- 同功能跨来源检索按片段区分度加权，并按需求文本长度归一化，避免长需求仅凭字符覆盖数量挤掉直接依据。
- 最终澄清检查先构造完整证据输入，再按 repair 节点目标预算分批；相近未决点排序后进入相邻批次，每项澄清恰好接受一次有效性检查。
- 调度器、桌面重试入口与真实验收脚本共用 `CURRENT_PIPELINE_VERSION`，不再分别写死版本号。

## 验证

- 保存的真实任务快照回放：前四项包含 R-0026“再次生成版本时重新检查版本范围”。
- 35 条长需求与 35 项澄清的调度反例：由“repair 提示 32,434 tokens 后失败”变为分批完成并进入 `needs-attention`。
- `npm test`：16 个测试文件、211 项测试通过。
- `npm run typecheck`：通过。
- `npm run build`：TypeScript、Vite 生产构建和 Electron 编译通过。
- `npm start`：本地页面返回 HTTP 200；Electron 主进程 PID 838380、渲染进程 PID 653288 均在本轮构建后启动。

## 边界
