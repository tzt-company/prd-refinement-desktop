# Round 16：单项证据分片与跨批澄清一致性

## 原因与修复

原分批逻辑只拆问题列表，既不能拆单个问题的关联需求，也没有跨批合并。现在使用完整问题、需求、来源三级分片；存在删除或修订建议时独立汇总所有分片理由，只能选用已校验动作或保留问题。批内动作暂存后再按问题组对核对全部剩余问题，合并与明确区分相互矛盾时不能通过。

调用按请求指纹写入检查点，全部检查成功前不提交暂存修改。pipeline 15 不与旧契约检查点混用。新增模块仅封装澄清编排，模型适配、证据编译、提示预算、并发槽位及持久化继续使用现有实现。

## 验证

- `npm test`：16 个测试文件、218 项全部通过，新增 7 项测试；完整套件耗时 55.67 秒。
- `npm run typecheck`：通过。
- `npm run build`：TypeScript、Vite 生产构建与 Electron 编译通过。
- 本地 `npm start` 重启：页面 HTTP 200，主进程 PID 584124 在本轮构建之后启动，编译产物版本为 pipeline 15。仅验证启动，不将 HTTP 200 计为真实 PRD 语义验收。
- 相同模拟反例回放：35 个相同决定先分为 9/9/9/8，跨批核对后仅保留 1 项。
- 单个澄清关联 12 条长需求：由 21,968 tokens 失败，变为分片最高 11,553 tokens，完整覆盖十二条需求及全部来源后正常进入 needs-attention。
- 20 个不同业务对象的同名问题：190 对全部进入跨批核对，仍保留 20 项。
- 分片产生删除候选与冲突：汇总收到全部分片理由，分别验证保留或采用已校验删除动作的路径。
- 跨批 Runtime 故障：不提前提交批内合并，重试不重复完成的有效性分片；取消同样保留原始 35 项。

原样例回放证据：`round-16/reproduction.json`。正式回归场景位于 `tests/scheduler.spec.ts`，不依赖 docs/tmp 中的临时脚本。

## 边界

上述调度测试使用模拟模型，证明分片覆盖、预算、合并动作及恢复协议，不证明任意真实模型都能给出正确语义判断。单个不可拆分条目或裁决请求自身超过硬预算时仍明确失败，不截断后标记检查通过。跨批问题组数增加时组对检查数量按平方增长，使用现有并发槽位调度。冻结 PRD 新版本的独立重复运行与并发耗时验收仍未完成。
