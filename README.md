# 需求细化平台

面向定版大 PRD 的需求细化桌面工作台。将原文组织为业务功能分组、跨功能约束、需求明细和待澄清事项，直接关联来源，再生成供开发 Agent 继续实施的结构化需求包。平台不接入目标项目源码，不生成原子规则中间层、技术方案、测试用例或验收场景；PRD 原文明示的字段、接口、数据要求、技术约束和验收条件仍然保留。

## 当前开发状态

包含任务中心、多个任务并行、节点耗时与进度、HTML/DOC/DOCX/PDF/Markdown/TXT 导入、统一 Runtime 配置、检查点恢复及 Excel 自动生成。确定性建账、字符覆盖、引用校验和 Excel 生成使用脚本；来源持久保存章节、表头和列表引导语，后续节点继续使用这些上下文。

任务完成后从同一需求快照编译 `requirements.json`、按功能组织的 Markdown、Excel 和来源索引。功能名称由模型生成，只用于人工导航；功能层其余职责是原文分组与约束适用关系，不生成目标或摘要，需求明细仍是唯一业务表述。Excel 默认显示阅读说明与汇总、功能清单、需求明细、待处理事项、检查记录和原文追踪，来源处置与审查历史默认隐藏。页面和可见工作表用文件、章节、位置及原文呈现证据，内部来源编号只保留在机器追溯数据中。

分析执行状态与需求交付状态分开。业务澄清分为阻塞、建议、可忽略三级：阻塞项和有效的平台整理问题进入 `drafts/`；仅有建议或可忽略项时可以进入正式 `deliveries/`，但这些事项仍保留在交付包中，不能自动写成确定需求。需求检查通过不表示开发实施已经验证，也不构成自然语言语义百分之百零遗漏证明。

待处理事项统一展示业务澄清和平台整理问题，但明确标出处理方。每条新业务澄清必须说明已知事实、唯一未决点、影响、分级依据和原文证据；建议项还要给出暂不处理时沿用的明确口径。事项只关联实际受影响的功能或需求，不扩散到同功能但来源无关的其他需求。

## 本地运行

```bash
npm install
npm start
```

在 macOS 上生成当前 CPU 架构的 DMG 安装包和 ZIP 包：

```bash
npm run dist:mac
```

在 Windows 上生成安装版和便携版：

```powershell
npm run dist:win
```

产物写入 `dist-release/`。打包验证使用 `node scripts/packaged-smoke.mjs <应用可执行文件> <证据目录>`，它会在独立用户数据目录启动应用、检查首页并截图。Mac 的可执行文件位于 `dist-release/mac*/需求细化平台.app/Contents/MacOS/需求细化平台`。

平台使用统一的 `AnalysisRuntime` 契约，当前提供两种适配器：Codex CLI 直接调用官方 CLI 并复用其管理的认证（持久化标识仍为 `codex-oauth`）；`dsh` 使用官方 SDK profile 和换行分隔 JSON-RPC stdio。Runtime 配置可填写 `http`、`https` 或 `socks5` 代理地址，连接检测与新任务会将其显式注入模型子进程，不依赖桌面应用是否继承终端环境；代理地址暂不支持用户名和密码。每个任务创建时固化不含密钥的适配器、模型、推理深度和代理地址快照；运行时通过系统配置引用解析凭据。DeepSeek API Key 使用 Electron `safeStorage` 加密保存，仅注入 DSH 子进程环境，不进入任务 JSON 或任务事件。

执行进度逐节点按职责说明该任务固化的模型与推理深度；多模型节点分别写明处理对象和用途，确定性脚本节点明确标记不使用模型。节点执行次数显示为“累计业务调用”。节点成本分布按真实调用的节点、模型与推理深度分组，避免不同执行配置的消耗被合并。

行为、条件、约束和原文明示验收条件都必须逐字段选择冻结原文证据；缺少 `evidenceBindings` 的当前模型输出直接失败，控制器不会再用整条需求来源自动补齐字段证据。原文明示验收条件由程序根据模型选择的证据编号取回，空数组表示原文没有明示验收条件。任何未知、过期或越权证据编号都会使节点失败，不会被静默丢弃。

模型请求会把重复的来源结构上下文提取为共享引用，并把原文证据编译为保留全部空白的不重叠句段；请求内证据使用 E1、E2 等短编号，来源对象省略文件哈希、修订和调度状态。大功能细化、审计、确认和复核按完整来源或需求分片执行，达到预算先拆包。每次实际尝试在发送前分别记录字符数、字节数、估算 Token、请求哈希、各分区长度和排队时间；候选类、审计类、修正类分别执行 12k、16k、20k 的硬预算。估算值只用于应用侧预算，不冒充供应商实际 Token。

每份候选内容的候选与分类、检查结果和返工预算、每功能细化结果、审计批及增量提交均有持久化检查点。当前检查点版本为 15；旧版结果保留查看，但旧版未完成任务必须用同版本原材料创建新任务，不能混用契约续跑。调度器、桌面重试入口和真实验收脚本共用版本常量。问题编号由结构化身份生成，不随审计顺序和说明措辞重排；成立确认绑定问题依赖版本，来源已承接结论绑定实际需求及其内容指纹。局部修正持久化计划、候选、复核和提交状态，复核中断后直接提交已复核候选。重试只恢复未完成工作，不清空问题、确认和预算。

最终澄清检查按完整提示预算拆问题，单个问题关联范围较大时继续按完整需求及对应原文分片；分片不裁剪文本，并覆盖全部相关来源。存在修订或删除候选时独立汇总各片理由，不能用多数票覆盖冲突。批内动作暂存后再跨批核对全部问题组对，确认业务对象、触发条件、未决规则一致才能合并；同名或同问法不自动合并。合并与保持独立的判断矛盾时检查失败。分片和跨批调用按请求指纹持久化，失败或取消不提交部分修改，重试复用已完成分片；全部通过后才提交澄清快照。单个不可拆分条目或裁决请求本身超过硬预算仍明确失败，不能截断或跳过后声称已检查。

每份原文包独立识别候选内容；功能统一必须提供每个候选的保留/合并/拆分映射，不按名称猜测来源归属。默认只发送候选，有争议时按需补充原文。每条需求恰好有一个主所属功能，共享来源不会自动产生多个主归属。

统一按完整业务能力整合同一对象的字段属性、联动与附录，概览映射到具体功能，不设置数量目标。统一发现文档记法、表头等被误识别为产品要求时只返回分类问题；控制器将受影响原文包定点退回候选识别，统一节点不直接删除原文。分类反馈持久化且有界。纯表头属于上下文，标题中明确的新增、重命名仍保留业务含义。

统一采用紧凑来源映射：候选只有一个目标时，脚本合并其全部来源，避免模型重复抄写编号；候选拆至多个目标时，必须先读取对应原文，再明确提供各目标的来源分配，脚本校验分配覆盖全部候选来源。不能用名称相似度补齐来源，也不能省略拆分分配。

候选识别、检查和统一共用来源分类契约：仅数量统计或章节索引且未表达具体行为的摘要归上下文，不要求独立功能；摘要中独有的具体业务要求仍须保留。返工预算耗尽时保留失败，不因手动重试重置次数。

统一节点同时接收该批候选的来源分类账本，功能引用上下文不等于将其视为产品要求。初次统一使用当前候选批分类，边界返工使用本轮修正后的分类，避免旧账本引发误报。

产物依据核查按原文包读取实际关联的需求及关系端点，并将模型返回的关系事实写入结果。问题确认和局部复核读取直接需求、同源依赖以及同功能内最多四条高相关需求。无冲突问题组可并行生成和复核，但所有通过的修正必须在最新项目上依次提交，避免并发结果相互覆盖。无法形成执行计划的问题保留为平台问题并结束处理，不会空循环。交付前逐项检查待澄清是否已被明确需求回答。最终页面状态和真实任务验收同时以五类检查、未验证范围及开放问题为准。

当前流程不以“模型再次扫描全文并宣称零遗漏”为目标。程序只验证已有产物的证据、结构、关系和交付条件；模型返回空问题不能消除程序已经确认的问题。结果允许保留有据可查的业务待澄清，用户可在统一调整入口补充后生成新版本。

审计问题必须定位真实对象；整项遗漏尚未形成需求编号时，直接以原文 S 编号作为影响对象，不用空数组或虚构需求编号。

Runtime 配置支持图片读取、候选识别、候选返工、候选检查、功能统一、简单细化、复杂细化、审计及局部修正各自的模型与推理深度。默认均使用 low：图片读取、候选识别、简单细化用 Luna；候选返工、功能统一、复杂细化、局部修正用 Terra；候选完整性检查和全量审计用 Sol。普通字段属性不会仅因“默认/必填/校验”字样升级。当前细化按大证据包或迁移、联动、例外等关系选择复杂路由，该启发式仍需质量对照评估。

最大并行任务默认 5（可配置 1–8），单任务节点并发默认 10（可配置 1–10）；每个任务有独立硬并发上限，全局模型调用槽位按两者的有效配置乘积约束。任务不设置总时长截止，持续执行到完成、需要关注、失败或用户取消；每次模型尝试最多等待 120 秒。页面分别显示点击到结果的完整耗时、模型活跃耗时、排队时间、格式重试，以及 Runtime 提供的 input/cached/output Token；缓存输入属于总输入子集，不重复相加。Runtime 未提供 Token 时显示缺失，不估算费用。

Codex 失败信息记录本次调用的结构化原因并脱敏，不显示原始 stderr。失败页提供“从失败处继续”和“重新开始”：继续执行复用已完成检查点，不重置返工预算、不重新生成已保存候选或再次提交已经接受的增量修正；重新开始复用该任务的冻结输入和当前 Runtime 配置创建独立新任务，旧失败记录继续保留。交付准入要求来源、功能、需求内容、关系、澄清五类检查都对同一个结果版本有效；缺失、过期或 UNKNOWN 均保持平台未完成。未返回用量的失败调用不能按零成本统计。局部修正的模型输出连续两次未通过结构或引用校验时，该尝试记为无效，原审计问题保持开放。Runtime、网络或进程故障不按输出错误处理，仍使任务失败并允许重试。

结构或引用校验失败时，第二次请求只携带具体校验错误及原始节点请求，不重复注入整份无效响应；仍最多两次且重新计量完整请求。来源位置由程序从冻结原文生成证据目录，模型只选择证据编号，不复制 quote 或计算字符位置；失败响应和节点、批次、校验原因保存在任务诊断目录。解析协议升级后，旧任务使用同版本资料包重新建账并创建新任务，不拼接旧检查点。枚举错误显示截断后的非法值和允许范围，不将非法值静默归类。

## 审计返工与图片读取

流程固定为七个用户可理解的阶段：原文建账、功能候选识别、功能清单统一、逐功能细化、产物依据核查、有据修正、交付。用户补充说明在建账后先被逐项解释为业务事实、范围决定、整理要求、疑问或替换口径；范围决定由程序确定性应用，处理结果可在任务详情回看。候选内容、功能和独立修正可有界并行；脚本负责建账、确定性校验、顺序提交修正和 Excel 生成。

任务持有原文与节点配置快照；新任务重新生成分析产物。原文或模型配置有变化时应新建任务，不修改执行中任务的输入。

最终澄清检查使用 pipeline 16：单个问题证据超预算时先按完整来源提取事实、定义、条件和例外，再联合原文推导答案。每片无法单独回答不代表需要业务确认；联合结论还需按实际提示预算逐片复核。复核发现遗漏时重新提取受影响来源，原始证据报告保存在任务检查点。汇总压缩仍不能满足预算时明确报平台处理失败，不截断后通过。

跨批去重显式区分相同、不同、未确定。未确定不构成“不同”，但未得到其他相同关系证明时仍须重审；明确不同与相同证据链冲突时作废涉及的判断。缓存区分候选、已验证和已否决，原文与协议参与依赖指纹；失败只重审失效工作，单份判断最多三次，次数跨重启保留。耗尽后报告具体平台问题，不新增业务澄清。全部检查通过才提交项目修改；取消或故障不会提交半成品。

本地更新先运行 `npm run build`，确认没有运行中的任务后关闭旧桌面进程，再执行 `npm start`。仅刷新页面不会更新 Electron 调度代码。旧版检查点不能直接续跑新协议；通过已保存的同版资料重新发起任务，历史结果保留。

DOCX 枚举包内图片，PDF 每页渲染 PNG 保存文字、图表与矢量内容。Codex 通过 --image，DSH 通过官方 SDK image content block 发送图片；图像转录保留在 asset.extractedText 中，原始文件、SHA-256 和位置可追溯。视觉结果不是人工完整性证明。无法辨认的图像、不支持格式、DOCX嵌入附件及尚未解析的图表/页眉页脚等已上传内容明确阻断，不会自动标记覆盖。Markdown 中指向其他文件的路径不用于判断资料是否缺失。

## 结果调整与 Agent 交付

完成或需要业务确认的结果页上方提供一个任务级调整输入区。用户可以一次描述多个功能的颗粒度调整、补充业务口径和回答多项澄清，平台负责定位受影响内容并生成一个新版本；无需逐个打开功能或澄清填写。草稿跨结果标签保留并自动保存，提交失败时输入不丢失，原版本保持只读。

任务详情以“功能与需求 / 全部需求 / 待处理事项 / 执行记录”组织，完成任务默认进入功能范围工作台。功能和需求都可批量标记“本期不做”或恢复本期；复选框只用于一次批量操作，行内标签显示已保存范围。交付包读取当前版本的本期范围，同时保留相关待处理事项和本期不做清单，不因存在澄清而拒绝生成。

“生成交付包”和“打开产物”具有独立状态：任务完成或生成成功后按结果版本刷新产物状态，记录确切版本和目录；打开失败不会要求重新生成。任务可归档、恢复或删除；删除使用应用内确认并说明托管数据边界，运行中的管理操作会先停止执行。

运行 `npm test`、`npm run typecheck`、`npm run build`、`npm run verify:premium` 验证本地实现。

固定原文样本位于 `tests/fixtures/ilcd-gold.json`。在项目目录执行：

```powershell
node scripts/evaluate-gold.mjs tests/fixtures/ilcd-gold.json <原始PRD路径> <任务JSON路径> <评测结果JSON路径>
```

评测核对原文哈希与来源关联，输出关键事实词面保真情况。评测器版本 2 支持待确认项直接引用原文；旧结果必须用相同评测器重新计算后才能比较。它能作为回归探针，但不能判断所有否定/关系/合理拆分，不能称为全文语义召回率或100%零遗漏。语义判断另行记录PASS/FAIL/UNKNOWN及需求ID证据，真人复核状态单列。

配置页显示 CLI 的真实版本、可执行文件路径与认证状态。刷新状态执行 `--version` 和 `login status`（各限时 10 秒），不调用模型；未知输出或命令失败显示检查失败，不当作未登录。Runtime 连接检测使用当前表单中的适配器、主模型和代理发送一次最小请求，不逐节点串行探测。首次认证请在终端运行该可执行文件的 `login` 命令，再回到配置页刷新状态。
Electron preload 使用 .cts 编译为 .cjs，以在默认沙箱中提供 IPC 接口；保留 contextIsolation，关闭渲染进程 Node 集成。
检查反馈固定在运行时信息顶部：区分状态读取与模型连接，按钮显示忙碌状态并防止重复点击；失败保留已有结果并提供重试，成功显示更新时间。

HTML/HTM 按声明编码解析静态正文、标题和表格，不执行脚本；data 图片、内联 SVG 和 iframe `srcdoc` 作为文件自身内容读取，指向其他文件或网络地址的路径不跟随、不用于判断缺件。旧版 DOC 在 macOS 上使用系统自带 `textutil` 转换，在 Windows 上需要本机安装 Microsoft Word 和 PowerShell 7，以禁用宏、只读方式转换为 DOCX 后解析；转换限时 60 秒，原文件不改写。PDF 保留逐页文本与完整页面图像。用户上传文件本身选择或解析失败时在上传页显示原因，可重试。
桌面程序同一用户数据目录只运行一个实例；重复启动会唤起已有窗口，避免多个窗口加载不同版本的导入筛选器。
新建任务页首先选择定版主 PRD；主文档保存后可添加补充文件、历史参考或资料目录，并在一个选填输入区集中描述背景、业务补充、范围调整、细化要求和澄清结论。支持多文件和目录拖放。目录保留相对路径，默认以目录名挂载，可在目录选项中修改。点击一次“开始分析”后，平台自动读取资料、建立索引并创建任务；文件进度会如实显示，不要求用户单独操作索引。

已保存的资料包可从“继续上次准备”中恢复；选中后可直接重命名或整体删除。删除前必须在页面内再次确认；删除会清理该资料包保存的文件快照、索引和缓存，不会删除原始磁盘文件，也不影响已创建分析任务中固定的输入快照。

资料包上限为 1000 文件、单文件 100 MiB、总计 500 MiB、100000 来源单元。超限明确报错，不截断目录；未知格式、符号链接、空文档和无法读取的已上传内容逐项登记。是否需要补充其他资料由用户决定。主 PRD 不能排除。支持文档、常用图片和 SVG；用户上传的 CSS/JS 只作来源数据，不执行脚本。

资料准备只读取用户实际上传的文件，不扫描引用路径，不自动读取旁边磁盘资料或下载网络资源，也不判断是否缺件。用户上传的每个文件独立进入索引；是否还要添加目录或其他文件由用户决定。动态脚本源码不等于所有交互状态均已读取。

“资料明细与读取记录”默认折叠，展开后可按关键词和文件过滤、分页、查看原文。后续分析按全部来源建账，检索命中不能代替完整性检查。任务同时锁定资料包版本和用户说明版本；说明中的明确业务决定进入用户来源，整理要求只调整输出方式，疑问继续作为待确认内容。主 PRD 限定基础范围，普通补充/历史资料不得自动覆盖或扩展；用户明确修改的具体口径优先，未裁决冲突形成待澄清。

资料清单、原始快照、解析缓存和索引保存于用户数据目录的 materials 子目录（macOS 默认 `~/Library/Application Support/prd-refinement-desktop/materials`，Windows 默认 `%APPDATA%/prd-refinement-desktop/materials`）。图像在索引阶段调用配置的图片模型，转录按图像哈希与模型配置缓存；索引就绪不等于语义完整。取消或重启中断均保留文件清单，不把半成品标为就绪。Windows 瞬时文件占用只对原子改名做有界重试，持续失败仍报错，保留旧清单。

HTML 内嵌 srcdoc/data 文档递归读取（最多 8 层），普通排版不阻断；内联脚本与样式源码作为来源数据保留，不执行。外部文档和缺失资源不跟随、不阻断；用户直接上传但不支持或无法读取的媒体仍明确报错。
