# 需求细化平台

面向大 PRD 的需求细化桌面工作台。将原文组织为业务功能、跨功能约束、需求明细和待澄清事项，直接关联来源，不生成原子规则中间层。平台不推导测试用例、验收场景或技术方案；PRD 原文明示的字段、接口、数据要求和验收条件仍然保留。

## 当前开发状态

包含任务中心、多个任务并行、节点耗时与进度、HTML/DOC/DOCX/PDF/Markdown/TXT 导入、统一 Runtime 配置、检查点恢复及 Excel 自动生成。确定性建账、字符覆盖、引用校验和 Excel 生成使用脚本；来源持久保存章节、表头和列表引导语，后续节点继续使用这些上下文。

结果工作簿默认显示阅读说明与汇总、功能清单、需求明细、待确认事项和需求审查问题五张业务主表；来源处置、原文追踪与审查历史默认隐藏。明细直接显示原文和位置，关联编号支持工作簿内跳转。所有机器整理结果均待人工审阅，不把 reviewed 当成人工确认。每项内容保留行为、条件、限制、来源及 PRD 原文明示验收条件。审计未通过或存在待澄清项时，任务可以完成产出，但结果不会被标记为语义审计通过。

待确认事项直接关联原文时，也显示在使用该原文的功能及需求行，并可跳转到待确认表；不会扩散到同功能但来源无关的其他需求。

## 本地运行

```powershell
npm install
npm start
```

生成 Windows 安装版和便携版：

```powershell
npm run dist:win
```

产物写入 `dist-release/`。打包验证使用 `node scripts/packaged-smoke.mjs <win-unpacked中的exe> <证据目录>`，它会在独立用户数据目录启动应用、检查首页并截图。

平台使用统一的 `AnalysisRuntime` 契约，当前提供两种适配器：Codex CLI 直接调用官方 CLI 并复用其管理的认证（持久化标识仍为 `codex-oauth`）；`dsh` 使用官方 SDK profile 和换行分隔 JSON-RPC stdio。每个任务创建时固化不含密钥的适配器、模型和推理深度快照；运行时通过系统配置引用解析凭据。DeepSeek API Key 使用 Electron `safeStorage` 加密保存，仅注入 DSH 子进程环境，不进入任务 JSON 或任务事件。

执行进度逐节点按职责说明该任务固化的模型与推理深度；多模型节点分别写明处理对象和用途，确定性脚本节点明确标记不使用模型。节点执行次数显示为“累计业务调用”。节点成本分布按真实调用的节点、模型与推理深度分组，避免不同执行配置的消耗被合并。

原文明示验收条件保持逐字引用；当模型把多个关联原文单元的完整片段仅用分号串成一项时，校验器无损拆回多项。任何不能完整归属于关联原文的字符仍会使节点失败，不会被静默丢弃。

模型请求会把重复的来源结构上下文提取为共享引用，来源编号、原文和位置保持不变。成本区域分别显示模型活跃耗时与跨执行代次的等待重试时间；任务进度中的总时长明确为墙钟时长。

每份候选内容的候选与分类、检查结果和返工预算、每功能细化结果、审计批及增量提交均有持久化检查点。当前检查点版本为 3；旧版结果保留查看，但旧版未完成任务必须用原材料新建，不能混用契约续跑。取消立即使执行代次失效，提交前后均检查代次；同一任务的文件保存串行化。

每份候选内容独立推进候选识别→只读检查→必要时定点返工，全部候选内容通过才进入功能统一。每份候选内容最多两轮返工，手动重试也不会重置预算。统一必须提供每个候选的保留/合并/拆分映射，不按名称猜测来源归属；默认只发送候选，有争议时按需补充原文。每条需求恰好有一个主所属功能，共享来源不会自动产生多个主归属。

统一按完整业务能力整合同一对象的字段属性、联动与附录，概览映射到具体功能，不设置数量目标。节点 4 发现文档记法、表头等被误识别为产品要求时只返回分类问题；控制器将受影响包定点退回节点 2/3，节点 4 不直接删除原文。分类反馈持久化，最多两轮，复用每包两轮候选修正预算。纯表头属于上下文，标题中明确的新增、重命名仍保留业务含义。

统一采用紧凑来源映射：候选只有一个目标时，脚本合并其全部来源，避免模型重复抄写编号；候选拆至多个目标时，必须先读取对应原文，再明确提供各目标的来源分配，脚本校验分配覆盖全部候选来源。不能用名称相似度补齐来源，也不能省略拆分分配。

候选识别、检查和统一共用来源分类契约：仅数量统计或章节索引且未表达具体行为的摘要归上下文，不要求独立功能；摘要中独有的具体业务要求仍须保留。返工预算耗尽时保留失败，不因手动重试重置次数。

统一节点同时接收该批候选的来源分类账本，功能引用上下文不等于将其视为产品要求。初次统一使用当前候选批分类，边界返工使用本轮修正后的分类，避免旧账本引发误报。

节点 6 按原文包全量审计，携带相关需求的完整来源证据。功能边界问题由控制器回到候选/统一责任节点，最多完成一轮边界修正，只重建变化功能及受影响审计包。条目问题只修正涉及的 R/Q，冲突写集合合并；独立复核通过后才串行分配新增编号，并原子提交数据和问题状态。原文歧义和未分类问题保持未决，不自动推断业务答案。交付前重新执行全局唯一编号、主归属、来源处置和引用校验。

细化补漏后仍未关联的来源交给节点 6，并保留脚本生成的遗漏问题，模型返回空问题不能消除这些事实。局部修正必须解决自身来源缺口、不能新增未覆盖，范围外已有缺口留给相应修正；交付最终仍要求全局零未覆盖。

审计问题必须定位真实对象；整项遗漏尚未形成需求编号时，直接以原文 S 编号作为影响对象，不用空数组或虚构需求编号。

Runtime 配置支持图片读取、候选识别、候选返工、候选检查、功能统一、简单细化、复杂细化、审计及局部修正各自的模型与推理深度。默认均使用 low：图片读取、候选识别、简单细化用 Luna；候选返工、功能统一、复杂细化、局部修正用 Terra；候选完整性检查和全量审计用 Sol。普通字段属性不会仅因“默认/必填/校验”字样升级。当前细化按大证据包或迁移、联动、例外等关系选择复杂路由，该启发式仍需质量对照评估。

任务并发与单任务节点并发分别有界；跨任务模型调用另有最多 8 路的全局上限。记录 Runtime 提供的 input/cached/output Token，缓存输入属于总输入子集，不重复相加。Codex 每次调用仍启动独立 exec；复用适配器对象不代表复用模型上下文。DSH 尚未提供调用 Token 指标，界面保留缺失状态，不估算费用。

Codex 失败信息记录本次调用的结构化原因并脱敏，不显示原始 stderr。失败时保留已完成检查点；从检查点重试不会重置候选返工预算，也不会重新提交已经接受的增量修正。未返回用量的失败调用不能按零成本统计。局部修正的模型输出连续两次未通过结构或引用校验时，候选整体拒绝、原审计问题保持开放；仍未承接的原文转为显式待人工确认项，已有数据和伪造内容均不改写。Runtime、网络或进程故障不按输出错误处理，仍使任务失败并允许重试。

结构或引用校验失败时，第二次请求携带上次响应作为待修正数据、具体校验错误及原始节点请求；仍最多两次。枚举错误显示截断后的非法值和允许范围，不将非法值静默归类。

## 审计返工与图片读取

流程固定为：原文建账、功能候选识别、功能候选完整性检查、功能清单统一、逐功能细化、完整性与忠实性检查、局部修正、交付。完整性检查只报告问题，由流程控制器把受影响候选内容定点退回候选识别，复核通过后才进入一次全局统一。候选内容和功能可有界并行；脚本负责建账、确定性校验、完全重复项处理和 Excel 生成。节点默认使用 Luna/Terra/Sol 的 low 配置，具体分工见上文 Runtime 配置。

任务持有原文与节点配置快照；新任务重新生成分析产物。原文或模型配置有变化时应新建任务，不修改执行中任务的输入。

DOCX 枚举包内图片，PDF 每页渲染 PNG 保存文字、图表与矢量内容。Codex 通过 --image，DSH 通过官方 SDK image content block 发送图片；图像转录保留在 asset.extractedText 中，原始文件、SHA-256 和位置可追溯。视觉结果不是人工完整性证明。无法辨认的图像、不支持格式、DOCX嵌入附件及尚未解析的图表/页眉页脚等已上传内容明确阻断，不会自动标记覆盖。Markdown 中指向其他文件的路径不用于判断资料是否缺失。

## 质量评测

运行 `npm test`、`npm run typecheck`、`npm run build`、`npm run verify:premium` 验证本地实现。

固定原文样本位于 `tests/fixtures/ilcd-gold.json`。在项目目录执行：

```powershell
node scripts/evaluate-gold.mjs tests/fixtures/ilcd-gold.json <原始PRD路径> <任务JSON路径> <评测结果JSON路径>
```

评测核对原文哈希与来源关联，输出关键事实词面保真情况。评测器版本 2 支持待确认项直接引用原文；旧结果必须用相同评测器重新计算后才能比较。它能作为回归探针，但不能判断所有否定/关系/合理拆分，不能称为全文语义召回率或100%零遗漏。语义判断另行记录PASS/FAIL/UNKNOWN及需求ID证据，真人复核状态单列。

配置页显示 CLI 的真实版本、可执行文件路径与认证状态。刷新状态执行 `--version` 和 `login status`（各限时 10 秒），不调用模型；未知输出或命令失败显示检查失败，不当作未登录。检测模型连接独立验证当前节点模型。首次认证请在终端运行该可执行文件的 `login` 命令，再回到配置页刷新状态。
Electron preload 使用 .cts 编译为 .cjs，以在默认沙箱中提供 IPC 接口；保留 contextIsolation，关闭渲染进程 Node 集成。
检查反馈固定在运行时信息顶部：区分状态读取与模型连接，按钮显示忙碌状态并防止重复点击；失败保留已有结果并提供重试，成功显示更新时间。

HTML/HTM 按声明编码解析静态正文、标题和表格，不执行脚本；data 图片、内联 SVG 和 iframe `srcdoc` 作为文件自身内容读取，指向其他文件或网络地址的路径不跟随、不用于判断缺件。旧版 DOC 需要本机安装 Microsoft Word 和 PowerShell 7，以禁用宏、只读方式转换为 DOCX 后解析；转换限时 60 秒，原文件不改写。PDF 保留逐页文本与完整页面图像。用户上传文件本身选择或解析失败时在上传页显示原因，可重试。
桌面程序同一用户数据目录只运行一个实例；重复启动会唤起已有窗口，避免多个窗口加载不同版本的导入筛选器。
新建任务页首先沿用单文件入口选择主 PRD，后台同时建立资料包；主文档保存后才展开补充文件、历史参考、资料目录和索引操作。支持多文件和目录拖放。目录保留相对路径，默认以目录名挂载，可修改包内路径。添加只保存草稿，点击“识别与建立索引”后展示逐文件进度；索引就绪才可“开始需求分析”。

已保存的资料包可从“继续上次准备”中恢复；选中后可直接重命名或整体删除。删除前必须在页面内再次确认；删除会清理该资料包保存的文件快照、索引和缓存，不会删除原始磁盘文件，也不影响已创建分析任务中固定的输入快照。

资料包上限为 1000 文件、单文件 100 MiB、总计 500 MiB、100000 来源单元。超限明确报错，不截断目录；未知格式、符号链接、空文档和无法读取的已上传内容逐项登记。是否需要补充其他资料由用户决定。主 PRD 不能排除。支持文档、常用图片和 SVG；用户上传的 CSS/JS 只作来源数据，不执行脚本。

资料准备只读取用户实际上传的文件，不扫描引用路径，不自动读取旁边磁盘资料或下载网络资源，也不判断是否缺件。用户上传的每个文件独立进入索引；是否还要添加目录或其他文件由用户决定。动态脚本源码不等于所有交互状态均已读取。

“内容索引”支持关键词和文件过滤、分页、原文查看。后续分析按全部来源建账，检索命中不能代替完整性检查。来源编号含文件身份、文件修订和解析版本，任务锁定资料包版本；补件生成新版本并重新分析，旧结果保留。主 PRD 限定范围，补充/历史资料不得自动覆盖或扩展，冲突形成待澄清。

资料清单、原始快照、解析缓存和索引保存于用户数据目录的 materials 子目录（Windows 默认 `%APPDATA%/prd-refinement-desktop/materials`）。图像在索引阶段调用配置的图片模型，转录按图像哈希与模型配置缓存；索引就绪不等于语义完整。取消或重启中断均保留文件清单，不把半成品标为就绪。Windows 瞬时文件占用只对原子改名做有界重试，持续失败仍报错，保留旧清单。

HTML 内嵌 srcdoc/data 文档递归读取（最多 8 层），普通排版不阻断；内联脚本与样式源码作为来源数据保留，不执行。外部文档和缺失资源不跟随、不阻断；用户直接上传但不支持或无法读取的媒体仍明确报错。
